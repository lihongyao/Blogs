# 概述

本文分享了一个适用于多品牌、多主题、多皮肤场景的前端实现方案。通过环境变量管理品牌配置、React Context 共享外观状态、动态布局加载及主题皮肤分层设计，实现了高扩展、低耦合的多品牌系统架构。

## 背景与目标

为支撑业务的快速扩展，我们需要在统一的前端框架下实现以下能力：

☑️ 支持多品牌的灵活定制；

☑️ 支持多主题 + 多皮肤组合，实现快速派生；

☑️ 能够在 Cloudflare Pages/Workers 上高效部署与缓存。

## 概念定义

| **概念** | **定义**                                             | **举例**                                      | **备注**             |
| :------- | ---------------------------------------------------- | --------------------------------------------- | -------------------- |
| 主题     | 控制页面结构与组件形态，<br />如间距、圆角、布局规则 | Modern：大间距、卡片化；<br />Classic：紧凑型 | 类似 Layout          |
| 皮肤     | 控制配色体系和视觉氛围，影响品牌感知                 | Light / Dark / VIP                            | 调节视觉情绪         |
| 品牌配置 | 指定使用的主题和皮肤，可支持局部样式覆盖             | 例如 A 品牌：Modern + Dark，主色可覆盖        | 可在构建或运行时加载 |

# 任务目标

搭建一个支持 **多主题、多皮肤、多品牌** 的方案，使用 **Next.js 16 + App Router**，同时支持 **SSR 与 CSR**。

项目将提供完整示例、结构说明和关键实现，并解决 **FOUC 问题**。

场景设定：

- 框架：`Next.js 16` + `App Router`
- 主题：`modern` `classic`
- 皮肤：`light` `dark`
- 品牌：`afun` `bfun`
- 样式简洁，以演示核心逻辑为主。

# 实现

## 分析

我们可以用两种思路来实现多主题 / 多皮肤方案：	

1. **运行时切换**

   这种方式最灵活，允许用户在页面中实时切换主题、皮肤或品牌。

   核心思路是将用户选择存入 Cookie，这样 **SSR 和 CSR** 都能读取到相同设置，保证渲染一致。

   - **持久化逻辑**

     - 用户的主题 / 皮肤选择存入 Cookie。
     - 页面刷新时，服务端会根据 Cookie 重新渲染，确保样式一致。

   - **SSR 逻辑**

     1. 优先读取 Cookie 中的主题设置。
     2. 如果 Cookie 不存在（首次访问），从默认配置中读取。
     3. 默认值作为最终兜底方案。

   - **资源管理**
     - 将所有主题和皮肤资源放在 public 目录，服务端可以直接使用，
     - 这样可以有效避免 **FOUC（样式闪烁）**

2. **构建时确定**，这种方式简单粗暴：在构建阶段就固定主题和皮肤，运行时无法切换，适合单品牌或单主题场景。

<hr/>

**📒 详细实现：运行时切换 + Public 目录资源**

1. 配置
   - 定义可用主题和皮肤（可来自设计稿或 Figma）。
   - 定义品牌信息：品牌 ID、默认主题 / 皮肤、覆盖样式（overrides）。
2. 环境变量
   - 通过环境变量在构建时指定当前品牌
3. SSR 样式加载
   - 在 \<head> 中动态加载对应品牌 / 主题 CSS。
   - 加载优先级：Cookie > 品牌配置 > 默认值。
   - 确保首屏 SSR 即加载正确样式，防止 **FOUC**。
4. 客户端同步切换
   - AppearanceContext 提供全局主题上下文。
   - useAppearance Hook 在组件中获取或更新主题状态。
   - AppearanceSwitcher 组件提供切换 UI。

### 服务端：获取品牌配置

> `src/lib/appearance.ts`

```ts
// src/lib/appearance.ts

import { cookies } from "next/headers";
import { brandConfigs, DEFAULT_BRAND } from "@/configs/brands";
import type { BrandConfig, BrandId, Skin, Theme } from "@/configs/brands/types";

/**
 * SSR 读取包网信息
 * 优先级：cookie > 环境变量 > 默认包网
 */
export async function getAppearance(): Promise<BrandConfig> {
  const BrandId = process.env.NEXT_PUBLIC_BRAND_ID as BrandId | undefined;

  const baseConfig =
    BrandId && brandConfigs[BrandId] ? brandConfigs[BrandId] : DEFAULT_BRAND;

  const cookieStore = await cookies();
  const theme = cookieStore.get("theme")?.value as Theme | undefined;
  const skin = cookieStore.get("skin")?.value as Skin | undefined;

  return {
    ...baseConfig,
    theme: theme ?? baseConfig.theme,
    skin: skin ?? baseConfig.skin,
  };
}
```

### 客户端：共享主题配置

> `src/providers/AppearanceProvider.tsx`

```tsx
// src/providers/AppearanceProvider.tsx

// pnpm add js-cookie
// pnpm add @types/js-cookie -D

"use client";

import Cookies from "js-cookie";
import { createContext, useCallback, useMemo, useState } from "react";
import type { BrandConfig, Skin, Theme } from "@/configs/brands/types";

export interface AppearanceContextValue {
  brand: BrandConfig;
  setTheme: (t: Theme) => void;
  setSkin: (s: Skin) => void;
}

export const AppearanceContext = createContext<AppearanceContextValue | null>(
  null,
);

export interface AppearanceProviderProps {
  initialBrand: BrandConfig;
  children: React.ReactNode;
}

/**
 * AppearanceProvider：接收 SSR 注入的初始包网配置
 */
export default function AppearanceProvider({
  initialBrand,
  children,
}: AppearanceProviderProps) {
  const [brand] = useState(initialBrand); // SSR 注入的数据，一旦注入永不变

  const setTheme = useCallback((newTheme: Theme) => {
    Cookies.set("theme", newTheme, { path: "/", expires: 365 });
    window.location.reload();
  }, []);

  const setSkin = useCallback((newSkin: Skin) => {
    Cookies.set("skin", newSkin, { path: "/", expires: 365 });
    window.location.reload();
  }, []);

  const value = useMemo(
    () => ({ brand, setTheme, setSkin }),
    [brand, setTheme, setSkin],
  );

  return (
    <AppearanceContext.Provider value={value}>
      {children}
    </AppearanceContext.Provider>
  );
}

```
> `src/hooks/useAppearance.tsx`
```tsx
// src/hooks/useAppearance.tsx
import { useContext } from "react";
import {
  AppearanceContext,
  type AppearanceContextValue,
} from "@/providers/AppearanceProvider";

/**
 * Hook：任何 Client 组件中直接使用
 */
export function useAppearance(): AppearanceContextValue {
  const ctx = useContext(AppearanceContext);
  if (!ctx) throw new Error("useAppearance must be used within ThemeProvider");
  return ctx;
}
```

说明：

- AppearanceProvider
  - 接收 **SSR 注入的初始品牌配置**，作为应用初始状态。
  - 提供 setTheme 和 setSkin 方法，用户切换时会更新 Cookie 并刷新页面，以触发服务端组件重渲染，保证 SSR/CSR 同步。
  - 使用 useMemo 缓存上下文值，避免不必要的重新渲染。
- useAppearance Hook
  - 在任意客户端组件中使用，方便获取当前品牌配置及切换方法。
  - 保证调用安全，必须在 AppearanceProvider 内部使用。

### 根布局 

> `src/app/[lang]/layout.tsx`

```tsx
// src/app/[lang]/layout.tsx
import "@/styles/globals.css";
import { getAppearance } from "@/lib/appearance";
import { ThemeLayouts } from "@/components/layout/themes";
import AppearanceProvider from "@/providers/AppearanceProvider";

type Props = {
  children: React.ReactNode;
  params: Promise<{ lang: string }>;
};

export default async function RootLayout({ children, params }: Props) {
  // SSR 获取品牌配置 & 主题布局
  const brand = await getAppearance();
  const Layout = ThemeLayouts[brand.theme];

  return (
    <html lang={lang} data-theme={brand.theme} data-skin={brand.skin}>
      <head>
        {/* SSR 加载主题、皮肤、覆盖文件 */}
				<link rel="stylesheet" href={`/styles/skins/${brand.skin}/index.css`} />
				<link rel="stylesheet" href={`/styles/themes/${brand.theme}/index.css`} />
				{brand.overrides && (<link rel="stylesheet" href={`/styles/overrides/${brand.id}.css`} />)}
      </head>
      <body className="w-full min-h-screen flex justify-center items-center">
        <AppearanceProvider initialBrand={brand}>
          <Layout>{children}</Layout>
        </AppearanceProvider>
      </body>
    </html>
  );
}
```

```ts
#!/usr/bin/env node
// scripts/build-styles.ts

import fs from "node:fs";
import path from "node:path";

/* -------------------------------------------------------------
 * 1️⃣ 解析命令行参数（支持 --brandId=xxx 与 APP_ENV=dev）
 * 优先级：--brandId=xxx > NEXT_PUBLIC_BRAND_ID(from .env.<env>) > 默认 'afun'
 * ------------------------------------------------------------- */
const args = process.argv.slice(2);

let brandId = "afun"; // 默认包 ID
let appEnv: string | undefined;

// 解析 args，两类形式都支持： "--brandId=xxx" 与 "APP_ENV=dev"
for (const arg of args) {
  if (arg.startsWith("--brandId=")) {
    brandId = arg.split("=")[1];
  } else if (arg.startsWith("APP_ENV=")) {
    appEnv = arg.split("=")[1];
  }
}

// 如果没从 args 得到 APP_ENV，也尝试从环境变量读取（以防某些 shell 将其导出为 env var）
if (!appEnv && process.env.APP_ENV) {
  appEnv = process.env.APP_ENV;
}

/* -------------------------------------------------------------
 * 2️⃣ 如果有 APP_ENV，读取对应的 .env.<env> 文件并解析
 * 目标：从 .env.dev 中取 NEXT_PUBLIC_BRAND_ID 的值，作为 brandId（优先级低于 --brandId）
 * ------------------------------------------------------------- */
function parseDotenv(content: string): Record<string, string> {
  const res: Record<string, string> = {};
  const lines = content.split(/\r?\n/);
  for (let line of lines) {
    line = line.trim();
    if (!line || line.startsWith("#")) continue; // 跳过空行和注释
    const idx = line.indexOf("=");
    if (idx === -1) continue;
    const key = line.slice(0, idx).trim();
    let value = line.slice(idx + 1).trim();
    // 去掉可能的引号
    if (
      (value.startsWith('"') && value.endsWith('"')) ||
      (value.startsWith("'") && value.endsWith("'"))
    ) {
      value = value.slice(1, -1);
    }
    res[key] = value;
  }
  return res;
}

if (appEnv) {
  try {
    const projectRoot = process.cwd();
    const envFile = path.join(projectRoot, `.env.${appEnv}`);
    if (fs.existsSync(envFile)) {
      const envContent = fs.readFileSync(envFile, "utf-8");
      const parsed = parseDotenv(envContent);
      if (parsed.NEXT_PUBLIC_BRAND_ID) {
        // 仅在没有通过 --brandId 指定时使用 .env 中的值
        // （如果想让 .env 覆盖命令行，可调整此逻辑）
        if (!args.some((a) => a.startsWith("--brandId="))) {
          brandId = parsed.NEXT_PUBLIC_BRAND_ID;
          console.log(
            `🟢 APP_ENV=${appEnv} -> NEXT_PUBLIC_BRAND_ID=${brandId}`,
          );
        } else {
          console.log(
            `🟡 NEXT_PUBLIC_BRAND_ID found (${parsed.NEXT_PUBLIC_BRAND_ID}) but --brandId was provided, keeping --brandId value: ${brandId}`,
          );
        }
      } else {
        console.log(
          `⚪ .env.${appEnv} found but NEXT_PUBLIC_BRAND_ID not set.`,
        );
      }
    } else {
      console.log(
        `⚪ .env.${appEnv} not found at: ${path.join(projectRoot, `.env.${appEnv}`)}`,
      );
    }
  } catch (err) {
    console.error("❌ 读取 .env 文件时出错：", err);
  }
} else {
  console.log("⚪ APP_ENV 未指定，使用默认或命令行指定的 brandId。");
}

/* -------------------------------------------------------------
 * 3️⃣ 加载包配置（ESM 动态导入 TS 模块）
 * 注意：此处保留你原有的导入方式（未更改业务逻辑）
 * ------------------------------------------------------------- */
const url = `../src/configs/brands/${brandId}.ts`;
const brandModule = await import(new URL(url, import.meta.url).pathname);
const key = `${brandId}Config`;
const brandConfig = brandModule[key];

/* -------------------------------------------------------------
 * 4️⃣ 准备输出目录
 * ------------------------------------------------------------- */
const projectRoot = process.cwd();
const outDir = path.join(projectRoot, "public", "styles");

// 清空旧文件并重建目录
fs.rmSync(outDir, { recursive: true, force: true });
fs.mkdirSync(outDir, { recursive: true });

console.log("\n");

/* -------------------------------------------------------------
 * 5️⃣ 合并主题（Theme）CSS
 * ------------------------------------------------------------- */
console.log("🗃️  themes");
const themeDir = path.join(
  projectRoot,
  "src/configs/themes",
  brandConfig.theme,
);
const themeFiles = ["tokens.css", "theme.css"];

let themeContent = "";
themeFiles.forEach((file) => {
  const filePath = path.join(themeDir, file);
  if (fs.existsSync(filePath)) {
    themeContent += `${fs.readFileSync(filePath, "utf-8")}\n`;
    console.log("👀 read theme file:", filePath);
  }
});

const themeOutFile = path.join(outDir, `${brandId}.theme.css`);
fs.writeFileSync(themeOutFile, themeContent);
console.log("✅ Theme CSS written to:", themeOutFile);
console.log("\n");

/* -------------------------------------------------------------
 * 6️⃣ 合并皮肤（Skin）CSS
 * ------------------------------------------------------------- */
console.log("🗃️  skins");
const skinDir = path.join(projectRoot, "src/configs/skins", brandConfig.skin);
const skinFiles = ["tokens.css", "skin.css"];

let skinContent = "";
skinFiles.forEach((file) => {
  const filePath = path.join(skinDir, file);
  if (fs.existsSync(filePath)) {
    skinContent += `${fs.readFileSync(filePath, "utf-8")} \n`;
    console.log("👀 read skin file:", filePath);
  }
});

const skinOutFile = path.join(outDir, `${brandId}.skin.css`);
fs.writeFileSync(skinOutFile, skinContent);
console.log("✅ Skin CSS written to:", skinOutFile);
console.log("\n");

/* -------------------------------------------------------------
 * 7️⃣ 拷贝 overrides.css（如存在）
 * ------------------------------------------------------------- */
console.log("🗃️  overrides");
const overrideFile = path.join(
  projectRoot,
  "src/configs/overrides",
  `${brandId}.css`,
);

if (fs.existsSync(overrideFile)) {
  const dest = path.join(outDir, "overrides.css");
  fs.copyFileSync(overrideFile, dest);
  console.log("✅ Overrides CSS copied to:", dest);
}

/* -------------------------------------------------------------
 * 8️⃣ 打印构建完成信息
 * ------------------------------------------------------------- */
console.log("\n🎉 Build complete!");
console.log("Brand:", brandId);
console.log("Theme:", brandConfig.theme);
console.log("Skin:", brandConfig.skin);
console.log("Output directory:", outDir);
console.log("\n");
```

# 资源接入指南（面向美术）

## 主题皮肤变量

### 概述

无论是主题（Theme）还是皮肤（Skin），都应采用 **分层设计**：

- 基础变量（tokens）

  定义原子级单位，例如间距、圆角、字体大小、颜色值等，与语义化无关，仅提供可复用的基础值。

- 语义化变量（theme/skin）

  将基础变量映射为语义化命名，例如 `--box-radius: var(--md)` 或 `--colors-text-brand: var(--colors-gold-100)`。

  用于描述布局、组件或视觉元素的语义意义。

### 独立性与兼容性

- 每套主题或皮肤都是 **独立资源库**，互不干扰。

- 主题和皮肤与品牌无直接绑定关系。

-  美术在设计主题或皮肤时，应保证其 **兼容不同品牌**，这样任意品牌都可以自由应用任意主题或皮肤。

> 可以理解为：
>
> - 主题 = 独立布局资源库
> - 皮肤 = 独立视觉资源库
> - 品牌 = 从主题和皮肤资源库中选择所需物料

### 资源目录规范（以 Figma 为例）

```
.
├── overrides             # 覆盖样式，主要用于后期微调，这里无需 tokens，直接匹配语义化变量，然后给具体色值进行覆盖
│   └── afun      
├── skins                 # 皮肤
│   ├── dark              # 皮肤名称
│   │   ├── skin          # 皮肤语义化变量，如 --colors-text-brand:var(--colors-gold-100)
│   │   └── tokens        # 皮肤基础变量，如 --colors-gold-100: #BC6D16FF
│   └── light             
│       ├── skin
│       └── tokens
└── themes                # 主题
    ├── classic           # 主题名称
    │   ├── theme         # 主题语义化变量，如 --box-radius:var(--md)
    │   └── tokens        # 主题基础变量，如 --md: 8px
    └── modern 
        ├── theme
        └── tokens
```

命名规范：

- **统一使用英文小写字母**

- 多单词变量使用 **连字符（-）** 连接
- 避免使用中文或大小写混用
- 目的是保证前端加载、查找和动态切换资源时的稳定性

> 通过这种方式，可以清晰区分 **基础变量、语义化变量、主题、皮肤和品牌覆盖**，保证多主题、多皮肤、多品牌的可扩展性和维护性。

注意事项：

在定义颜色类变量时，请遵循以下原则：

1. **避免在图层上直接使用透明度**
   - 尽量不要通过图层本身的透明度来实现视觉效果，以便前端可以通过变量灵活控制颜色。
2. **内边框处理**
   - 避免使用渐变透明或半透明颜色实现内边框。
   - 如果必须使用内边框，请使用 **纯色不透明**。
3. **外边框处理**
   - 如果不需要内边框，而通过外边框实现效果，可以使用颜色 + 透明度组合。

## 图片资源管理

美术在导出图片资源给前端时，请按照以下格式组织文件：

```ts
skin/{skin_name}/{brand_name}/{module_name}/{resource_name}.{png|jpg|svg|json|...}
```

示例：

- 皮肤名称：skin01
- 品牌名称：afun
- 模块名称：recharge
- 资源： banner

对应文件目录示例：

```
skin01/
└── afun/
      └── recharge/
          ├── banner_h5.png       # H5 专用
          ├── banner_pc.png       # PC 专用
          ├── banner_x1.jpg       
          └── banner_x2.svg      
```

命名规则：

1. 平台区分
   - H5 与 PC 不同的资源，文件名后加 _h5 或 _pc。
   - 如果 H5 与 PC 共用完全相同比例的图片，可省略平台标识，仅使用资源名。
2. 文件格式：
   - 支持 .png、.jpg、.svg、.json 等，保持统一规范。
3. 遵循 **英文小写 + 连字符** 的命名规范，避免空格、中文或大小写混用。

注意事项：

1. 设计图层分层：在导出图片资源前，请保持图层分明、合理命名，尽量将背景、图形、文字等元素分开独立图层。
2. 图文分离：除特殊字体或前端无法实现的效果外，应保持文字与图像分开，以便前端可通过配置或文本替换实现多语言适配。
3. 多语言可扩展性：保持文字独立图层，可以在不同语言环境下灵活替换文本，避免重新绘制整张图片或重新切图。

## 交付清单示例

| **类型**    | **文件**       | **备注**                           |
| ----------- | -------------- | ---------------------------------- |
| 主题        | tokens / theme | 间距、圆角、布局、组件规则         |
| 皮肤        | tokens / skin  | 颜色、阴影、渐变、氛围             |

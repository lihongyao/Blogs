在 next-intl 与 Next.js 16 App Router 下，路由弹窗由 URL 驱动：弹窗对应路径中的一段（如 `/modal-login`），支持前进/后退/刷新/分享，并与当前 locale 正确配合。下文为概述、按步骤的实现指南和注意事项。

---

## 概述

- **URL 形态**：在当前 pathname 后追加 modal 段，例如 `/` → `/modal-login`，或 `/en/details/1` → `/en/details/1/modal-login`。关闭时通过 `router.back()` 或去掉最后一段的 `router.replace` 实现。
- **服务端**：带 modal 段的请求需要在进入 App 前做一次 rewrite，让请求以「带 locale 的 base 路径」进入，这样 `[locale]` layout 的 `params.locale` 正确，next-intl 才能工作；同时浏览器地址栏仍是完整 URL，前端用 pathname 解析出 modal 段并渲染弹窗。
- **前端**：在 `[locale]` layout 里挂一个 `RouteModalRenderer`，从 pathname 里解析出所有在 `ModalComponents` 里注册的段，按顺序渲染对应组件，并统一处理关闭与 body 滚动；退出动画用 AnimatePresence，在 `onExitComplete` 后再隐藏，避免闪没。

---

## 实现指南

### 步骤一：next.config.ts 配置

在路由匹配前，把「仅含 modal 路径」的请求重写到默认语言路径，避免 App Router 把 `modal-login` 等误当成 `[locale]`。

```ts
// next.config.ts
import type { NextConfig } from 'next';
import createNextIntlPlugin from 'next-intl/plugin';
import brandConfig from './src/configs/brands';
import { ModalRoutes } from './src/libs/routes';

const defaultLocale = brandConfig.defaultLocale;
const modalRewrites = (Object.values(ModalRoutes) as string[]).map((path) => ({
  source: path,
  destination: `/${defaultLocale}`,
}));

const nextConfig: NextConfig = {
  reactCompiler: true,
  reactStrictMode: false,
  rewrites: async () => ({
    beforeFiles: modalRewrites,
  }),
};

const withNextIntl = createNextIntlPlugin();
export default withNextIntl(nextConfig);
```

含义：用户直接访问 `/modal-login` 时，先被重写到 `/{defaultLocale}`，请求以「有 locale 的路径」进入 app，`[locale]` 不会拿到非法 locale。

### 步骤二：proxy 中处理带 modal 的完整路径

Next.js 16 使用命名导出 `export function proxy`，在 `src/proxy.ts` 里先判断「当前 pathname 是否包含 modal 段」；若包含，则 rewrite 到「该 modal 之前的 base 路径」（并补上 locale），这样 layout 拿到的仍是「页面路径」，而浏览器地址栏不变，前端 pathname 仍是完整路径，可用来渲染弹窗。

```ts
// src/proxy.ts
import createMiddleware from 'next-intl/middleware';
import { type NextRequest, NextResponse } from 'next/server';
import { routing } from './i18n/routing';
import { ModalRoute, ModalRoutes } from './libs/routes';

const intlMiddleware = createMiddleware(routing);
const modalRouteValues = new Set(Object.values(ModalRoutes));
const defaultLocale = routing.defaultLocale;
const locales = routing.locales;

export function proxy(request: NextRequest) {
  const rewriteTarget = modalRewriteUrl(request);
  if (rewriteTarget) {
    return NextResponse.rewrite(rewriteTarget);
  }
  return intlMiddleware(request);
}

function modalRewriteUrl(request: NextRequest) {
  const { pathname, searchParams } = request.nextUrl;
  const modalRouteKey = matchModalRoute(pathname);
  if (!modalRouteKey) return null;

  const pathnames = pathname.split('/').filter(Boolean);
  const modalIndex = pathnames.findIndex((segment) => `/${segment}` === modalRouteKey);
  if (modalIndex === -1) return null;

  const basePaths = pathnames.slice(0, modalIndex);
  const hasLocalePrefix = basePaths.length > 0 && locales.includes(basePaths[0]);
  if (!hasLocalePrefix) {
    basePaths.unshift(defaultLocale);
  }
  const basePath = `/${basePaths.join('/')}`;

  const rewriteUrl = request.nextUrl.clone();
  rewriteUrl.pathname = basePath.replace(/\/{2,}/g, '/');
  rewriteUrl.search = searchParams.toString() ? `?${searchParams.toString()}` : '';
  return rewriteUrl;
}

function matchModalRoute(pathname: string) {
  const segments = pathname.split('/').filter(Boolean);
  for (let i = 0; i < segments.length; i++) {
    const seg = `/${segments[i]}`;
    if (modalRouteValues.has(seg as ModalRoute)) return seg;
  }
  return null;
}

export const config = {
  matcher: '/((?!api|trpc|_next|_vercel|.*\\..*).*)',
};
```

要点：只做「含 modal 段 → 重写到 base 路径」；locale 由 base 路径或补上的 `defaultLocale` 决定，next-intl 的 middleware 照常处理其它路径。

### 步骤三：目录与路由约定

- 弹窗组件放在 `app/[locale]/(modals)/` 下，`(modals)` 为路由组，不增加 URL 段。
- 在 `libs/routes.ts` 定义 modal 路径常量，在 `(modals)/index.ts` 做「段名 → 组件」映射并 dynamic 引入；`RouteModalRenderer` 只依赖 pathname 上的段与这份映射。

```
src/
├── app/[locale]/
│   ├── layout.tsx
│   ├── (main)/page.tsx
│   └── (modals)/
│       ├── index.ts      # ModalComponents
│       ├── login.tsx
│       └── profile.tsx
├── components/features/
│   └── RouteModalRenderer.tsx
├── hooks/
│   └── useModalRoutes.ts
├── i18n/
│   ├── routing.ts
│   └── navigation.ts
├── libs/
│   └── routes.ts         # ModalRoutes
└── proxy.ts
```

### 步骤四：定义 Modal 路径与组件映射

`src/libs/routes.ts`：

```ts
export const ModalRoutes = {
  ModalProfile: '/modal-profile',
  ModalLogin: '/modal-login',
} as const;
```

`src/app/[locale]/(modals)/index.ts`：key 与 URL 段一致（无前导斜杠）：

```ts
import type { ComponentType } from 'react';
import dynamic from 'next/dynamic';
import type { ModalComponentProps } from '@/components/features/RouteModalRenderer';

const ModalProfile = dynamic(() => import('@/app/[locale]/(modals)/profile'));
const ModalLogin = dynamic(() => import('@/app/[locale]/(modals)/login'));

export const ModalComponents: Record<string, ComponentType<ModalComponentProps>> = {
  'modal-profile': ModalProfile,
  'modal-login': ModalLogin,
};
```

### 步骤五：RouteModalRenderer 与弹窗 props

- 使用 `@/i18n/navigation` 的 `usePathname`、`useRouter`、`useSearchParams`，保证与 next-intl 一致。
- 从 pathname 解析段：`pathSegments.filter((s) => ModalComponents[s])` 得到 `modalKeys`，再得到组件列表。
- 关闭：优先 `router.back()`，否则从 path 去掉最后一段做 `router.replace`。
- 用 `AnimatePresence` 包住列表；路由变空时先不 return null，等 `onExitComplete` 再设 `pureHidden` 并 return null，这样退出动画能播完。
- 弹窗统一接收 `onCloseAction`，在 `RouteModalRenderer` 中定义并传入：

```ts
export type ModalComponentProps = {
  onCloseAction: () => void;
};
```

### 步骤六：在 layout 中挂载

在 `app/[locale]/layout.tsx` 中与 `children` 并列挂一次即可：

```tsx
import RouteModalRenderer from '@/components/features/RouteModalRenderer';

export default async function LocaleLayout({ children, params }) {
  // ...
  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider ...>
          {children}
          <RouteModalRenderer />
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

### 步骤七：打开与关闭弹窗

- **打开**：用 `useModalRoutes().getMergePath(ModalRoute)` 得到「当前 path + modal 段」，再用 `router.push(path, { scroll: false })` 或 `<Link href={...}>`。`useRouter`、`usePathname` 必须来自 `@/i18n/navigation`。
- **关闭**：弹窗内调用 `onCloseAction()`，由 `RouteModalRenderer` 内部执行 back 或 replace。

---

## 注意事项

- **pathname 来源**：所有读 pathname、做跳转的地方都用 next-intl 的 `usePathname` / `useRouter`，不要用 `next/navigation`，否则 locale 前缀会不一致。
- **next.config 的 rewrites**：`beforeFiles` 只处理「纯 modal 路径」到默认 locale 的映射，避免首屏把 `modal-xxx` 当成 locale；带 locale 的路径（如 `/en/modal-login`）由 proxy 的 rewrite 处理。
- **proxy 与 middleware**：先做 modal 的 rewrite，再走 next-intl 的 middleware，这样带 modal 的请求会以「base 路径 + 正确 locale」进入 app，layout 的 `params.locale` 才可靠。
- **退出动画**：不要在「路由变空」的当帧就 return null，否则 AnimatePresence 会被卸载，exit 播不出来；应在 `onExitComplete` 且当前无 modal 时再设 `pureHidden` 并 return null。
- **新增弹窗**：在 `ModalRoutes` 和 `ModalComponents` 各加一项，proxy 里的 `ModalRoutes` 与 next.config 的 `ModalRoutes` 保持一致即可，无需改 matcher。
